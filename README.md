## О проекте

Envoy согласует время и место встречи, цену, обмены, условия вступления и рекламные размещения. Владелец задаёт **мандат**: что для него важно и где проходят жёсткие границы. Агент торгуется внутри мандата, а всё, что за его пределами, передаёт владельцу.

Главная идея проекта: **решения принимает детерминированный движок, а не LLM**. Языковая модель только переводит между естественным языком и структурой. Из этого следуют три свойства:

| Свойство | Что это значит |
|---|---|
| Проверяемость | Можно доказать, что агент не превысил полномочия |
| Безопасность | Prompt injection не может привести к действию |
| Воспроизводимость | Одинаковые входы дают одинаковые решения |

Проект выполняется как курсовая по дисциплине «Технологии программирования» (ГУАП), но проектируется как реальная система. Упрощается объём работ, а не качество: архитектурные границы, тесты и безопасность остаются полными.

## Ключевые возможности

- **Мандат как закон.** Версионируемый, иммутабельный, подписанный документ. Каждое действие агента проходит `Authorizer` с вердиктом `Allow | Escalate | Deny`, по умолчанию `Deny`.
- **Настоящая переговорная логика.** Многокритериальная полезность, жёсткие ограничения, стратегии уступок (Boulware/Conceder, tit-for-tat, Zeuthen), байесовская модель оппонента, Парето-оптимальные пакеты, решение Нэша.
- **Протокол agent-to-agent.** Типизированные подписанные сообщения (Ed25519, CBOR), цепочка делегирования от владельца, защита от циклов, формальная проверка в TLA+. Если у собеседника нет агента, сессия переходит в диалог «человек ↔ агент» с тем же состоянием.
- **Приватность по построению.** Слепые торги и пересечение календарей через DH-PSI (Ristretto255), минимизация данных, разделение приватных и общих каналов.
- **Неизменяемый журнал.** Event sourcing, хэш-цепочка, подпись каждой записи, крипто-удаление содержимого без разрыва цепочки.
- **Исполнение обязательств.** Чек-листы, сроки, залог в Telegram Stars как saga с компенсациями, споры и арбитр, репутация.
- **Все поверхности Telegram.** Business-подключение, guest mode, inline, группы, Managed Bots, топики сессий, rich-карточки, виджеты.

## Как это работает

```
                  ┌─────────────────────────────────────────────┐
 Telegram ◄─────► │  telegram (adapter)                         │
                  └──────────────────┬──────────────────────────┘
                                     │ Inbound / Outbound ports
                  ┌──────────────────▼──────────────────────────┐
                  │  app: оркестрация сессий, use cases         │
                  │   ├─ security.InboundFilter                 │
                  │   ├─ llm.Translator    (NL ↔ структура)     │
                  │   ├─ security.Authorizer                    │
                  │   ├─ protocol          (A2A, подписи)       │
                  │   ├─ engine            (мандат, стратегии)  │
                  │   ├─ privacy           (PSI, коммитменты)   │
                  │   ├─ execution         (чек-лист, залог)    │
                  │   └─ journal           (hash-chain)         │
                  └──────────────────┬──────────────────────────┘
                                     │ Repository / Clock / Rng ports
                              PostgreSQL, хранилище ключей
```

Архитектура гексагональная: зависимости направлены только внутрь. Доменная логика и движок состоят из чистых функций без ввода-вывода, а Telegram, БД, LLM, время и случайность подключаются через порты. Правило проверяет `import-linter` в CI, нарушение роняет сборку.

### Жизненный цикл сессии

```
INIT ─► HANDSHAKE ─► NEGOTIATING ─► AGREED ─► COMMITTING ─► EXECUTING ─► CLOSED
                        │  ▲            │          │             │
                        ▼  │            ▼          ▼             ▼
                  PENDING_OWNER      REVOKED    ABORTED      DISPUTED ─► RESOLVED
```

Из любого нетерминального состояния достижимо терминальное: зависших сессий нет.

### Принципы

1. **LLM не решает.** Любой вывод модели считается недоверенным: схема, затем валидатор, затем `Authorizer`.
2. **Всё внешнее — данные.** Текст контрагента никогда не попадает в канал инструкций LLM.
3. **Минимум данных.** Контрагент и LLM получают только то, что нужно для текущего шага.
4. **Журнал первичен.** Состояние сессии — проекция журнала событий.
5. **Идемпотентность везде.** Любой обработчик безопасно перезапускается.
6. **Чистое ядро.** Весь ввод-вывод вынесен за порты.

## Технологии

| Область | Выбор |
|---|---|
| Язык | Python, `asyncio`, Poetry |
| Telegram | `aiogram` за собственным адаптером, прямые вызовы Bot API для новых методов |
| Web/API | FastAPI, uvicorn |
| Данные | PostgreSQL, SQLAlchemy 2 (async), Alembic, Pydantic v2 |
| Криптография | `cryptography` / PyNaCl, Ristretto255, `cbor2` |
| Оптимизация | OR-Tools (CP-SAT), NumPy, SciPy |
| Mini App | TypeScript, Telegram Mini Apps SDK, Vite |
| Качество | black, ruff, `mypy --strict`, import-linter |
| Тесты | pytest, Hypothesis, TLA+/TLC, testcontainers |
| Запуск | Docker Compose |

Версии зависимостей не фиксируются заранее: на момент реализации берутся актуальные стабильные.

## Запуск

Docker Compose появится в фазе 0. Целевой сценарий:

```bash
cp .env.example .env
make up
make migrate
make test
```

Все секреты (токены, ключи, `database_url`, `master_key`) хранятся только в `.env`. Файл исключён из git и из образов.

## Качество и безопасность

- Покрытие ядра не ниже 90 % по веткам, `mypy --strict` и `ruff` без замечаний.
- Каталог red-team атак как данные. Критерий: ноль действий вне мандата и ноль утечек.
- Property-тесты инвариантов: оффер всегда допустим, нет двойного accept, журнал обнаруживает любую правку.
- Модельная проверка протокола в TLA+ отдельной задачей CI.
- Ответ движка не дольше 2 секунд на раунд без LLM.

## Чего Envoy не делает

- Не заменяет юриста: результат сессии — договорённость в Telegram, а не юридически значимый договор.
- Не универсальный ассистент: только переговоры.
- Не платёжная система: деньги проходят через сменяемых провайдеров, в v1 это Telegram Stars как залог за цифровую услугу.
- На единой платформе не защищает от злонамеренного оператора, такая защита даётся только федерацией.
